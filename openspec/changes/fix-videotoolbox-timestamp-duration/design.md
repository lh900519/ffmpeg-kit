## Context

动机见 proposal.md。本规划保存在当前 `ffmpeg-kit` 仓库的 OpenSpec 中。原生修复在当前仓库的 `min_gpl` 分支实施；应用联动位于相邻的 `../superassistant`，其中 `lib/`、依赖声明及应用验证路径均相对于 superassistant。后续跨仓库修改须遵循实际工具写权限和各仓库指令。

- fork 的 `scripts/source.sh` 锁定 `arthenica/FFmpeg` 的 `n6.0`；`src/` 被忽略且当前为空。现有 iOS/macOS Podspec 使用 `min-gpl-local` 子规格，直接引用插件目录下八个 XCFramework。
- 应用当前实际使用 Git 依赖，业务项目中的 `path: ../ffmpeg-kit/flutter/flutter` 仍为注释。不能把本地源码变化误认为已进入应用。
- `VideoEdit.cut()` 在 Apple 默认使用 `hevc_videotoolbox`，仅按退出码判断成功。失败时使用持久化硬件禁用标记并递归软件重试，但漏传 `fps`。四处业务调用在得到路径后可能删除源缓存并上传。
- 五个导入入口及 `isAbnormalDuration()` 已有未提交改动，实施时保留并完善；其他用户修改不得覆盖。
- 样本编码器标记为 `Lavc60.3.100 hevc_videotoolbox`，447 帧、30 fps、音轨 14.978 秒，视频轨 495555.566667 秒；第二帧 PTS 17066496、时间基 1/15360，恰好符合微秒值 33333 被误当作 1/30 秒单位后的封装结果。这是高度吻合证据，不能单靠文件标签证明其由本项目生成。

## Goals / Non-Goals

**Goals:** 纠正平台返回时间单位的换算，确保输出验证失败能够触发现有软件回退，并交付应用实际加载的可追溯原生库。

**Non-Goals:** 不以调整 MP4 timescale、统一 `-r 30` 或 `setpts=PTS-STARTPTS` 替代编码器修复；这些选项无法纠正发生在编码器输出端的时间单位误读。其余范围见 proposal.md。

## Decisions

### 1. 在原 FFmpeg 6 基线上回移小补丁

保存 `patches/videotoolbox-timestamp-timescale.patch`，修改下载后 FFmpeg 的 `libavcodec/videotoolboxenc.c`：在 `vtenc_cm_to_avpacket()` 中校验 PTS 有效，按返回的 PTS/DTS 各自 timescale 用 `av_rescale_q` 换算到 `avctx->time_base`，保留现有无效 DTS 回退和 `dts_delta`，删除废弃局部变量。

在公共源码下载流程成功获取 FFmpeg 后应用补丁；先检查正向是否可应用，再检查反向是否表明已应用，否则终止。不能依赖被忽略的 `src/ffmpeg` 中一次性手改。保留原 fork 基线及 FFmpegKit 已有定制，不把源码仓库直接换成不含定制的上游。

替代方案：升级第三方发行版涉及 Flutter 原生依赖、GPL 编码器和 macOS 兼容，范围更大；仅补 Dart 参数无法修正编码器内部换算。

### 2. 重建并明确接入完整 Apple 产物

记录当前二进制架构、编码能力和构建配置，再用现有 `ios.sh` / `macos.sh` 生成完整 XCFramework 集合，保留 VideoToolbox、x264、x265 及现有 min-gpl 能力。输出来自 `prebuilt/bundle-apple-xcframework-ios/` 和 `prebuilt/bundle-apple-xcframework-macos/`，分别整体替换插件 `ios/Frameworks/ffmpeg-kit-ios-min-gpl/`、`macos/Frameworks/ffmpeg-kit-macos-min-gpl/`。禁止只覆盖某个设备切片而遗漏模拟器或 Catalyst。

构建记录包含 FFmpegKit/FFmpeg 提交、补丁标识、Xcode/SDK、命令、架构、产物 SHA-256；同版本号不足以区分是否修复。保留既有 framework 名称并执行项目的原生补丁与 archive 校验。

本地 path 依赖仅用于验证；最终更新 fork 插件版本并使用包含二进制的固定 Git 提交或标签及锁文件。仓库推送和远端发布按独立授权执行，未交付的原生产物不能把任务记为完成。

### 3. 在共享 cut 路径集中验证输出并有限重试

沿用 `Future<String?>` API。输入元数据需先经过有限数和异常时长检查；有效目标长度为请求长度与源视频减去起点后的剩余长度的较小值。请求长度为零的现有语义是处理剩余视频，不将其当成零秒期望值；负值或无法确定有效片段时按现有失败路径结束。保留裁剪参数精度，避免当前整秒格式化导致请求和校验基准不一致。

一次尝试必须同时满足退出码成功、输出存在、存在视频轨、视频轨时长有限且大于零，以及与目标长度偏差不超过 max(1 秒, 目标长度 × 5%)。音频及容器时长用于诊断，不能以正常音频或容器值覆盖异常视频轨。无音轨、缺少 nb_frames 不单独判失败。

硬件失败或校验失败都走至多一次软件尝试；软件尝试从原始输入开始，完整传递 fps（包括 -1 不强制帧率）、起止/长度、码率、声道、尺寸和输出参数。异常输出在重试前删除，软件失败时返回 null；已经禁用硬件时只尝试软件一次。保留现有硬件失败持久化标记的兼容语义，不批量重置旧用户设置。调整四个调用点保证验证成功前不删除输入、不上传异常文件。

替代方案：在每个页面重复探测容易遗漏；只检查六小时阈值会漏过较小幅度的时间轴错误；仅比较音视频时长无法覆盖无音轨视频。

### 4. 保留异常输入拦截并分开验证源损坏和编码缺陷

复用工作区已有 `isAbnormalDuration()`，先处理 null、NaN、Infinity 和非正数，避免转换 Duration 时异常。保留超过六小时和声明时长/帧率估算严重偏离的业务拦截，审查所有建立裁剪时间轴或批量缩略图的路径。共享 cut 也做防御检查；无需转码直接上传的分支应在入口验证可信时长。复用既有失败文案。

现有坏样本用来证明拦截生效，不能把对坏样本的重新编码成功当作原生补丁正确性证据。原生换算使用合成 CMTime 验证单位不变/变更、无效 PTS 和现有 DTS 回退；正常源视频在受影响设备上验证硬件输出。业务状态测试使用轻量 fake 隔离命令、元数据和上传，不真实启动 SDK 或访问网络；设备/构建验证作为单独集成验证记录。

## Risks / Trade-offs

- [新 Xcode 与旧原生构建脚本不兼容] → 当前本机 Xcode 27.2，先建立构建基线；兼容改动只限成功构建本补丁所需范围，记录失败原因，不以旧二进制冒充修复。
- [重试增加耗时和存储占用] → 最多一次软件重试，保留输入至成功校验，清理无效输出，日志记录尝试与失败原因。
- [时长边界和 VFR 导致误拒绝] → 对有效片段使用明确容差，测试源末尾、亚秒片段、无音轨及 VFR，不用 nb_frames 推算值取代输出真实时长。
- [设备上仍有其他时间戳问题] → 同时部署输出校验与有限回退，收集输入输出探测摘要及设备/系统/编码器信息；不记录视频内容。
- [跨仓库工作遗漏二进制或锁文件] → 以完整构建记录和最终依赖解析路径为交付证据。

## Migration Plan

1. 核对两仓库基线、已有工作区改动和原生能力，添加补丁及可重复构建文档。
2. 重建两个 Apple 平台并替换八库集合；校验架构、编码器和修复证据。
3. 临时使用本地 path 验证应用层输出校验、回退、输入拦截及 archive 脚本。
4. 更新 fork 版本，按授权交付固定源码/二进制版本；业务项目锁定新版本，移除临时 path。
5. 设备与集成验证完成后方可交付。回滚时恢复上一固定依赖与锁文件，可保留输出校验和软件回退防止坏结果上传。

无需迁移既有用户缓存、数据库、购买状态或生成模型；旧损坏文件继续被导入检查拒绝。现有硬件禁用用户仍使用软件编码，不自动强制重新启用。
